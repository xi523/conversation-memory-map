# 对话记忆地图规范

## 两张地图解决的不同问题

| 视图 | 核心问题 | 组织方式 | 更新时机 | 保留内容 |
|---|---|---|---|---|
| 对话思考地图 | 现在聊到哪里，为什么这样推进 | 总命题 → 讨论分支 → 当前焦点 | 人工触发同步时 | 状态、判断、理由、下一步 |
| 主题知识地图 | 这个主题已经沉淀了什么 | 主题 → 概念/结论/方法/证据/问题 | 结论稳定后 | 可复用知识、来源、边界、版本 |

前者是工作记忆，后者是长期记忆。不要用一张图同时承担两种任务。

## 思考地图节点模型

```yaml
id: stable-node-id
parent: parent-node-id
status: confirmed | active | future | parked
title: 一行短标题
note: 一行补充说明
reason: 为什么保留这个节点
conclusion: 当前形成的判断
next: 下一步动作或问题
updated_at: YYYY-MM-DD
```

状态变化：

- `active → confirmed`：已经形成当前可执行结论。
- `active → future`：有价值，但不是当前焦点。
- `active → parked`：明确不在范围内或当前不值得继续。
- `confirmed → active`：新证据使旧结论重新进入讨论。

## 视觉语法

- 固定从左向右阅读，根节点是总命题。
- 首屏优先控制为三到四列，主分支通常不超过五个。
- 只展开当前焦点路径，其他分支保持一层入口。
- 节点严格使用“状态 / 标题 / 一行说明”三段式。
- 绿色只表示已确认，红色只表示正在讨论，紫色只表示后面再展开，灰色只表示暂时放下。
- 当前路径的连接线更强，其他连线弱化。
- 点击节点后展示原因、结论和下一步。
- 详情区默认展示当前焦点和当前结论。
- 节点尺寸、间距、圆角和字体保持统一。
- 小屏允许横向滚动，不要把节点压缩到不可读。

应避免按时间线复述全部消息、把知识分类图误当思考地图、所有分支同时展开、在节点内写长段文字、用颜色区分主题、每次更新新建文件，以及依赖远程 D3。

## 主题知识节点模型

```yaml
id: canonical-topic-id
topic: 规范主题名
type: concept | decision | method | evidence | open-question
summary: 当前稳定结论
scope: 适用条件与边界
evidence: 依据或来源链接
status: stable | provisional | disputed | superseded
related: 关联节点 id
updated_at: YYYY-MM-DD
```

按照规范主题名去重。同义说法合并到同一节点并保留证据；真实冲突标注适用条件或争议状态，不静默覆盖。

## 知识提升规则

一个讨论结论满足以下多数条件时才进入主题知识地图：已经明确确认或形成可执行决策；对未来问题具有复用价值；适用范围清楚；依据或推导过程可追溯；与既有知识的关系可以说明为新增、补充、修正或替代。

正在讨论的内容可以进入开放问题，但不能作为稳定知识。暂时放下的节点通常不进入知识地图。

## 同步算法

1. 判断新消息是在延续节点、改变状态，还是形成独立分支。
2. 优先更新已有节点，避免重复。
3. 确定唯一的当前焦点并更新默认当前结论。
4. 检查已确认且可复用的结论是否需要沉淀。
5. 标注被修正或替代的知识，同时保留版本关系。
6. 原位更新已有文件，并刷新右侧主视图。

## 提示词示例

最短触发：

> 同步对话地图。

同步双地图：

> 使用 `$conversation-memory-map` 同步当前对话：更新从左到右的讨论状态图，只展开当前讨论分支，并把已经确认且具有复用价值的结论沉淀到主题知识地图。原位更新已有文件，在右侧打开思考地图。

只更新思考地图：

> 使用 `$conversation-memory-map` 只更新对话思考地图：根据最新讨论调整节点状态、当前焦点和下一步，不更新主题知识地图。

只做知识沉淀：

> 使用 `$conversation-memory-map` 检查本轮哪些内容已经形成稳定、可复用的结论；去重后同步到主题知识地图，保留依据、适用边界和版本变化，不要把未确认观点当成事实。
